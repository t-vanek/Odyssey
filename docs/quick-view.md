# Quick View

Press `F3` on one local file or one regular entry inside a supported archive in the active Commander panel. On the Remote page, select one regular file in the connected SFTP list and press `F3` or the Quick View button. Quick View is read-only and is available in Odyssey's default read-only mode. Double-click uses the same viewer for archive/SFTP files; directories still navigate normally.

The viewer reads one bounded block at a time. Choose 16, 32, 64, or 256 KiB, then use `Page Up`/`Page Down` or the navigation buttons to move through the file. `Ctrl+Home` and `Ctrl+End` jump to the first or last block. Loading can be cancelled. `Escape` closes the viewer after an active read has finished or been cancelled.

**Automatic** display uses text for detected text and hex for binary data. Text encoding is detected from UTF-8/UTF-16 byte-order marks and bounded content heuristics. The encoding list can force UTF-8, UTF-16 LE/BE, ISO-8859-1, or ASCII. **Hex** works for every accepted local or archive file and shows an absolute byte offset, sixteen bytes, and printable ASCII on each line.

Every local block is tied to the file length and modification timestamp captured when the viewer opened. An archive block is additionally tied to the archive length and timestamp and to the entry metadata. Odyssey refuses another block if that snapshot changes and also checks the container after each read. Local files, archive containers and all of their ancestors must be regular filesystem paths, not symbolic links or reparse points.

Archive Quick View first validates the complete entry catalogue through the same path-traversal, duplicate/case-collision, link, encryption, entry-count, depth, expanded-size and, where compressed-size metadata exists, compression-ratio policy used by extraction. It then streams the requested regular entry directly into fixed-size header and display buffers. It creates no extracted or persistent cache file. ZIP and plain TAR use managed readers; 7z, TAR.GZ, GZip, BZip2, XZ and RAR use the verified native engine only when that capability is available. A compressed stream may have to be decoded and discarded from the entry start to reach a later block, so cancellation bounds the work but block navigation is not constant-time. A block that ends before the entry end does not claim to validate an unseen compressed tail; the catalogue and declared safety limits are validated on every read.

SFTP Quick View uses only the opaque identity of the already connected, strictly host-key-verified session. Passwords and host-key material are not copied into the viewer, settings, queue, logs, or a temporary file. The remote path must be absolute and canonical; directories and reported symbolic links are rejected. The reader checks size and modification time, opens a cancellable seekable read stream, transfers only the 4 KiB detection header plus the selected block, then stats the file again. Later blocks must match the first version. A server that maliciously changes bytes while preserving both metadata values cannot be detected by this lightweight preview; no content-hash guarantee is claimed. Explicit disconnect closes an open SFTP viewer, while an unexpected disconnect is reported as a read failure that can be retried after reconnecting.

Current limits are intentional: encrypted and link/special archive entries and SFTP links are rejected rather than materialized. Syntax highlighting, images and EXIF, PDF rendering/text, media thumbnails/metadata, and rich document metadata are not implemented. Use the context-menu **Open** action to delegate an ordinary local file to the operating system or to navigate into a supported archive.
